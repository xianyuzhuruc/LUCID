# LUCID Hub 密码登录设计

## 背景

LUCID Hub 当前打开根页面后即可使用 Hub API、事件流和终端 WebSocket。远端 Agent 已通过独立 Token 保护，但浏览器访问的 Hub 没有登录边界。需要在进入 LUCID 前增加密码验证，并在首次运行时引导创建密码。

## 目标

- Hub 未配置密码时，首次访问显示创建密码界面。
- 密码只保存为带随机盐的不可逆哈希，不保存或回传明文。
- 登录成功后在当前浏览器保持登录 14 天。
- 同时保护 Hub 页面、HTTP API、SSE 和 WebSocket，避免仅遮挡前端页面。
- 远端 Agent 的 `/agent/v1/*` 继续使用现有 Token，不受 Hub 登录 Cookie 影响。
- 提供明确的退出登录入口，并限制连续密码尝试。

## 非目标

- 不增加用户名、多用户、角色或权限分级。
- 不替换 Agent Token 认证，也不把 Hub 密码同步到远端节点。
- 不提供找回密码服务；拥有服务器文件权限的管理员可以在服务器上执行受控重置。
- 不在浏览器 `localStorage`、`sessionStorage` 或可被 JavaScript 读取的 Cookie 中保存密码或会话密钥。

## 采用方案

采用“密码哈希文件 + 后端签名 Cookie”的无数据库方案。相比服务端会话表，它不需要维护会话数据库；相比 HTTP Basic Auth，它可以提供首次设密、退出登录和与 LUCID 一致的界面。

### 密码存储

新增独立认证模块，将认证配置保存在 `${LUCID_STATE_DIR:-~/.lucid}/auth.json`：

- 使用 Python 标准库 `hashlib.scrypt`，为密码生成独立随机盐和不可逆哈希。
- 文件同时保存随机生成的会话签名密钥和认证版本，不包含密码明文。
- 状态目录权限设置为 `0700`，认证文件通过临时文件原子替换并设置为 `0600`。
- 密码比较使用常量时间比较。
- 配置文件不存在表示首次设置；配置存在但损坏时安全拒绝，不允许把损坏状态当作首次设置覆盖。

首次密码至少 8 个字符，前端要求二次确认，后端再次独立校验。并发首次设置由进程锁保护，只有第一个有效请求能够成功。

### 14 天会话

登录成功后，后端签发带签名和签发时间的 `lucid_session` Cookie：

- `HttpOnly`，浏览器脚本无法读取。
- `SameSite=Lax`，降低跨站请求携带会话的风险。
- `Path=/`，`Max-Age=1209600`（14 天）。
- HTTPS 请求设置 `Secure`；HTTP 本地部署保持可用。
- 服务端验证 HMAC 签名、认证版本和 14 天有效期，任何篡改或过期都视为未登录。

退出登录会清除浏览器 Cookie。重置密码时轮换会话密钥和认证版本，使旧 Cookie 立即失效。

### 路由和协议保护

认证仅在 Hub 模式启用。

公开入口：

- `/login`：首次设密或登录页面。
- `/api/auth/status`：返回是否已配置密码及当前会话是否有效。
- `/api/auth/setup`：只允许在认证配置确实不存在时创建密码。
- `/api/auth/login`：验证密码并签发 Cookie。
- `/api/auth/logout`：清除 Cookie。
- `/favicon.ico`：登录页图标。

受保护范围：

- `/` 和其他 Hub 页面；浏览器页面请求未认证时重定向到 `/login`。
- `/api/*`（认证入口除外）；未认证时返回 JSON `401`。
- `/api/events` SSE；由 HTTP 认证层统一保护。
- `/api/nodes/*/terminal/ws` 等 Hub WebSocket；握手时校验 Cookie，失败以 `4401` 关闭。
- OpenAPI 和调试入口默认也受保护。

`/agent/v1/*` 及其 WebSocket 明确绕过 Hub Cookie 认证，继续调用现有 Agent Token 校验。

### 暴力尝试限制

后端按客户端地址维护短期、内存内的失败记录。连续失败达到阈值后暂时拒绝新的登录尝试，并返回通用错误，避免暴露密码是否接近正确。成功登录会清除该地址的失败记录。进程重启会清空限制记录，但密码哈希和会话签名密钥保持不变。

### 登录界面

新增独立 `static/login.html`，使用与 LUCID 现有界面一致的深色终端视觉，不依赖外部网络资源。

- 未配置时显示“创建访问密码”和确认输入框。
- 已配置时显示密码输入框和“进入 LUCID”按钮。
- 已经登录时访问 `/login` 自动返回主页面。
- 提交期间禁用按钮，错误在表单内显示，不把具体后端异常或敏感状态暴露给用户。
- 主页面增加退出登录按钮，调用退出接口后跳回 `/login`。

## 数据流

```text
首次访问 /                     后续访问 /
     │                              │
     ▼                              ▼
未配置 → /login 创建密码       校验 lucid_session Cookie
     │                              │
     ▼                         有效 ├─→ LUCID Hub
scrypt 哈希写入 auth.json           │
     │                         无效 └─→ /login
     ▼
签发 14 天 HttpOnly Cookie
     │
     ▼
进入 LUCID Hub
```

## 错误与恢复

- 错误密码只返回统一的认证失败消息。
- 认证文件损坏、字段缺失或权限异常时 fail closed，服务器日志记录原因，登录页提示联系管理员。
- Cookie 不存在、过期、签名错误或认证版本不匹配时统一按未登录处理。
- Agent 请求不依赖 Hub Cookie，因此不会因 Hub 认证文件问题中断节点 Token 通信。
- 管理员密码重置流程将以明确命令或文档说明实现，避免直接编辑哈希文件。

## 测试与验收

后端自动测试覆盖：

- 首次创建后文件不含明文、权限正确，正确/错误密码验证符合预期。
- 重复首次设置被拒绝，损坏认证文件不会被覆盖。
- 签名 Cookie 在 14 天内有效，篡改、过期和认证版本变化后失效。
- 未登录页面重定向、API `401`、SSE 保护和 WebSocket `4401`。
- `/agent/v1/*` 不进入 Hub Cookie 认证层。
- 登录失败限制和成功后清除失败记录。

浏览器验收覆盖：

- 全新状态首次打开显示创建密码页，确认不一致不能提交。
- 创建后自动进入主页面，刷新页面不要求重新登录。
- 重启 LUCID 后 Cookie 仍有效，最多保持 14 天。
- 无效或过期 Cookie 被送回登录页。
- 退出登录后主页面、API 和新 WebSocket 都无法继续访问。
- 登录后现有节点、Terminal、New Bash、SSE 状态更新仍正常。

## 变更范围

- 新增后端认证模块及对应测试。
- 在 `app.py` 中增加认证路由、Hub HTTP 保护和 Hub WebSocket 校验。
- 新增 `static/login.html`。
- 在 `static/index.html` 中增加退出登录入口，保留当前未提交的终端响应式和会话修复。
- 不修改远端 Agent 的认证协议或部署目录。
