# Nodes 固定排序设计

## 背景

Nodes 中间栏的数据来自两个入口：`GET /api/nodes` 按节点配置文件顺序返回，SSE 快照则按字符串 ID 排序返回。页面在首次访问、手动刷新和实时快照更新之间切换数据来源时，节点顺序会发生变化。

## 排序规则

- `local` 节点始终置顶。
- 其余节点按 ID 自然升序排列，数字片段按数值比较。
- ID 相同时以节点显示名称作为稳定的次级排序键。
- 不根据健康状态、窗口数量或请求完成时间排序，避免运行状态变化导致位置跳动。

当前节点的预期顺序为：`local`、`1`、`144`、`147`、`200`、`200_docker`。

## 实现

在前端状态对象中增加单一的节点排序函数。`refreshNodes()` 和 `applySnapshot()` 在写入 `this.nodes` 前都调用该函数，使首次加载、Nodes 面板刷新和 SSE 更新使用完全相同的规则。所有复用 `nodes` 的节点列表和下拉框会自然保持一致，无需修改后端协议或节点配置文件。

排序函数返回新数组，不原地修改 API 响应；缺少 ID 的异常条目排在普通远端节点之后，并使用空字符串安全比较。

## 测试

- 输入打乱的 `local`、纯数字 ID 和带文本后缀 ID，断言得到规定顺序。
- 分别调用 `refreshNodes()` 与 `applySnapshot()`，断言两个入口产生相同顺序。
- 运行现有前端 JavaScript 行为测试和完整 Python 测试。

## 变更范围

仅修改 `static/index.html` 的节点状态归一化逻辑并添加前端回归测试；不修改节点配置、部署顺序、后端 API 或健康检查。
