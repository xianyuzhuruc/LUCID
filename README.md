# LUCID — Cross-Server Terminal Monitor & Alert Dashboard

<div align="center">
  <a href="README.md">English</a> | <a href="README.zh-CN.md">中文</a>
</div>

LUCID is a web dashboard that lets you **monitor Claude Code, Codex, and shell
sessions across multiple servers** from a single browser tab. It watches every
terminal in real time, detects when a session **stops working** or **needs your
confirmation**, and surfaces those alerts so you never miss a prompt.

If you run several agent sessions on different machines, LUCID gives you one
place to see which sessions are busy, which are stuck, and which are waiting for
you — and lets you act on them immediately.

---

## What You Can Do With LUCID

### Cross-Server Terminal Monitoring

- See **all your Claude Code and Codex sessions** — local or remote — in one
  dashboard.
- Each session shows its current status: **Working**, **Waiting** (needs you),
  **Stalled** (stopped producing output), or **Bash**.
- Terminal output is captured every few seconds via tmux, so you can watch
  progress without attaching to each machine individually.
- The dashboard updates in real time via SSE — no page refresh needed.

### Status Alerts — Know When Something Needs You

LUCID classifies every managed terminal into one of three states:

| Status  | What It Means |
|---------|---------------|
| **Working** | The session is actively producing output. No action needed. |
| **Waiting** | The session needs your attention — a permission prompt, a yes/no question, or an error it can't resolve. **This is your cue to act.** |
| **Stalled** | The session has stopped producing new output. It may be stuck, finished, or waiting silently — worth checking. |

Waiting detection works by diffing successive tmux captures: if the output
hasn't changed and contains both "yes" and "no" (interactive prompt) or "error"
(something went wrong), LUCID marks it **Waiting** and surfaces it at the top of
the dashboard.

Additionally, LUCID reads `/tmp/claude-focus.log` for permission events
generated by Claude Code's notification hooks, so you get a second signal when
a session needs authorization.

### Multi-Server Architecture

```
Browser
  |
  v
local LUCID hub :21893
  |
  +-- HTTP over SSH tunnel --> server-a agent (127.0.0.1)
  +-- HTTP over SSH tunnel --> server-b agent (127.0.0.1)
```

- **Hub** runs on your local machine, serves the dashboard, and aggregates state
  from all nodes.
- **Agent** runs on each server, reads local tmux panes and process state, and
  reports back to the hub.
- Agents bind to `127.0.0.1` only — no public ports. The hub reaches them
  through SSH local port forwarding.
- One-click deployment from the UI: fill in host details, click deploy, and the
  hub sets up SSH keys, uploads the runtime, starts the agent, and opens the
  tunnel.

### Actions You Can Take From the Dashboard

For any session, on any server, you can:

| Action | What It Does |
|--------|-------------|
| **Focus** | Bring the terminal window/tab to the front (macOS Terminal.app, iTerm2, or tmux). |
| **Terminal** | View live terminal output and send keystrokes — no need to SSH in. |
| **Close** | Kill the managed session and its tmux pane. |
| **Resume** | Continue a previous Claude/Codex session from where it left off. |
| **Fork** | Clone a session into a new one with the conversation history. |
| **Review** | Run a background Claude review of the session's recent work and get a verdict (PASS / FAIL / PARTIAL). |
| **Rename** | Give the session a memorable name. |
| **Launch** | Start a new managed Claude, Codex, or Bash session — optionally on a remote server. |

### File Browser

Browse, read, upload, and delete files on any connected server — all through
the dashboard. Useful for checking outputs, grabbing logs, or tweaking configs
without opening a separate terminal.

### Session History & Search

- Browse past Claude and Codex conversation histories across all servers.
- Search across transcripts to find when and where something was discussed.
- View timelines of user messages, assistant responses, and tool calls.

### Knowledge Overview

- See extracted **skills**, **memories**, and **plans** from your agent sessions.
- Understand what your agents have learned and what they're working on across
  projects.

## Getting Started

### Prerequisites

- Python 3.10+
- tmux (for managed terminal sessions)
- Bash on Linux/macOS, or `run.bat` on Windows

### Start the Hub

```bash
git clone https://github.com/tianyilt/LUCID
cd LUCID
bash run.sh
```

Open:

```
http://127.0.0.1:21893
```

`run.sh` creates a virtual environment, installs dependencies, and starts the
server. To use a different port:

```bash
LUCID_PORT=21894 bash run.sh
```

### Add Your Local Machine

The hub starts without monitoring any sessions by default. To include the
machine the hub is running on:

1. Open the dashboard → **Nodes** panel.
2. Click **Enable local node**.

This adds a local node to `~/.lucid/nodes.toml` and the dashboard will start
showing managed sessions from your local machine.

### Launch a Managed Session

Use the dashboard's Launch panel, or from the command line:

```bash
# Start a managed Claude session in tmux
python -m core.terminal.runner run claude --tmux --cwd /your/project --display-name "my-task"

# Start a managed Codex session
python -m core.terminal.runner run codex --tmux --cwd /your/project

# Start a managed Bash session
python -m core.terminal.runner run bash --tmux --cwd /your/project
```

Managed sessions run inside tmux, which lets LUCID capture terminal output,
detect status changes, and provide terminal access from the dashboard.

### Deploy a Remote Agent

First, set up SSH key access to the remote server:

```bash
ssh-copy-id user@server
ssh user@server   # verify no password prompt
```

Then deploy from the UI:

1. Open the dashboard → **Nodes** panel.
2. Fill in: node id, host, SSH user, SSH port.
3. Leave agent port empty — LUCID picks a free port automatically.
4. Click **Deploy / update agent**.

The hub will upload the runtime, start the agent on the remote server, open an
SSH tunnel, and add the node to your configuration. Managed sessions on that
server will appear in the dashboard automatically.

### Manual Agent Setup

If you prefer to manage deployment yourself, start the agent on the remote
machine:

```bash
cd /path/to/LUCID
LUCID_MODE=agent LUCID_AGENT_HOST=127.0.0.1 LUCID_PORT=7879 bash run.sh
```

Create an SSH tunnel from your local machine:

```bash
ssh -N -L 17879:127.0.0.1:7879 user@server
```

Add to `~/.lucid/nodes.toml`:

```toml
[[nodes]]
id = "server-a"
kind = "ssh"
host = "server.example.com"
user = "user"
ssh_port = 22
local_port = 17879
agent_host = "127.0.0.1"
agent_port = 7879
url = "http://127.0.0.1:17879"
auto_tunnel = false
```

## How Status Detection Works

LUCID captures the last 30 lines of each tmux pane every 3 seconds. It compares
the current capture against the previous one:

- **Output changed** → **Working**. The session is producing new content.
- **Output unchanged + contains "yes" and "no"** → **Waiting**. The CLI is
  likely asking a yes/no question.
- **Output unchanged + contains "error"** → **Waiting**. Something went wrong
  and the CLI may be waiting for guidance.
- **Output unchanged + no markers** → **Stalled**. No new output and no
  detectable prompt — the session may be stuck or finished.

Waiting sessions are sorted to the top of the dashboard so you see them first.
The dashboard tab title also updates with a count when sessions need attention.

## Security

- Remote agents bind to `127.0.0.1` only — they are never exposed to the
  network.
- All remote access goes through SSH local port forwarding.
- Optional bearer-token authentication can be configured per node.
- **Use SSH keys** for deployment — password-based deployment stores the
  password in `~/.lucid/ssh-history.json` (file permissions `0600`, but
  plaintext).
- If you bind the hub to an address other than `127.0.0.1`, add authentication
  before exposing it to other users.
